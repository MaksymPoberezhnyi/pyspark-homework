## Try it 6: SCD Type 3, only the previous value <span class="tag">5 min</span>

Columns: `customer_id, name, city, tier, previous_city, city_changed_on`. Write
`scd3_merge(updates, path, effective_date)`:

- first load: write with `previous_city = NULL` and `city_changed_on = NULL`, **typed**
  (`sf.lit(None).cast("string")`). An untyped NULL column can't be written to Delta,
- MERGE on `customer_id` with **two** `whenMatchedUpdate` clauses. The first match wins, so order matters:
  1. city changed → `previous_city = t.city`, `city = s.city`, `city_changed_on = eff`, plus name and tier,
  2. only name or tier changed → update those, and **keep** `previous_city`,
- not matched → insert with NULL `previous_city`.

Compare with `<=>` (null-safe equality), not `<>`. Otherwise a NULL city on either side never counts as a change.

## Try it 7: SCD Type 4, current table plus history table <span class="tag">3 min</span>

Type 4 keeps the hot, small, **Type 1** table that 99% of queries hit, and puts the history in a
separate table. With Delta you get the history almost for free: enable the **Change Data Feed** on the
Type 1 table, and every `insert` / `update_postimage` *is* a historical version.

1. Make new tables get CDF by default:
   `spark.conf.set("spark.databricks.delta.properties.defaults.enableChangeDataFeed", "true")`
2. Run your `scd1_merge` for day 1–3, with an extra column `updated_on` = the load date.
3. Unset the conf, read the change feed, keep `insert` and `update_postimage`, and write the history table.
